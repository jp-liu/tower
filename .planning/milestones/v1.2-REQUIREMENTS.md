# Milestone v1.2 — Extensions & Slim Distribution

**Defined:** 2026-05-09
**Goal:** 把 ripgrep 和 Monaco 两个体积大头从核心代码里剥出来做成可选"扩展"。建立轻量统一的扩展模型（不是真插件系统），用户可在引导页 / Settings 一键启用或禁用。

**Phases:** 71-73 (continued numbering from v1.1)

---

## Extension Model — Phase 71

Build the unified Extension abstraction that backs both rg and Monaco today, and any future
"optional bundle" tomorrow. Replace the current ad-hoc `installRg` action and `copy-monaco.js`
postinstall script with a single registry + server-actions surface.

- [ ] **EXT-01**: Tower defines an `Extension` interface (id, name, description, icon, sizeMB, homepageUrl, check, install, optional uninstall) and a registry that exposes `listExtensions()` / `getExtension(id)`.
  - Files: new `src/lib/extensions/types.ts`, `src/lib/extensions/registry.ts`
  - Two definitions live in `src/lib/extensions/definitions/{ripgrep,monaco}.ts`

- [ ] **EXT-02**: Unified server actions `checkExtension(id)`, `installExtension(id)`, `uninstallExtension(id)`, `listAllExtensionStatus()`.
  - Files: new `src/actions/extension-actions.ts`
  - Replace direct callers of `checkRgAvailable` / `installRg` (kept as private helpers inside `definitions/ripgrep.ts`, no external imports)

- [ ] **EXT-03**: rg extension definition wraps existing logic.
  - check: dual-track — first try `@vscode/ripgrep` package binary, then fall back to `which rg` from system PATH
  - install: `pnpm add @vscode/ripgrep` (no sudo, no system pollution); package's own postinstall fetches the platform binary into `node_modules/@vscode/ripgrep/bin/rg`
  - uninstall: `pnpm remove @vscode/ripgrep`
  - homepageUrl: `https://github.com/BurntSushi/ripgrep#installation`

- [ ] **EXT-04**: Monaco extension definition.
  - check: verify both `node_modules/monaco-editor/package.json` exists AND `public/vs/loader.js` exists; pull version from package.json
  - install: `pnpm add monaco-editor` then run `node scripts/copy-monaco.js` to copy `node_modules/monaco-editor/min/vs` → `public/vs`
  - uninstall: `pnpm remove monaco-editor` + `rm -rf public/vs`
  - homepageUrl: `https://microsoft.github.io/monaco-editor/`

- [ ] **EXT-05**: Client-side `useExtension(id)` hook with shared cache.
  - Files: new `src/lib/extensions/client.ts`, new `src/lib/extensions/context.tsx`
  - Provides `{ status, loading, install, uninstall, refresh }`
  - Uses React Context + initial `listAllExtensionStatus()` mount to avoid duplicate per-component checks
  - Re-checks after install/uninstall actions

- [ ] **EXT-06**: Hot-reload — install/uninstall does NOT require app restart. After `installExtension` returns success, `useExtension` cache invalidates and consumer UI re-renders. New rg path is picked up at next searchCode call (clear `_rgPath` cache); new Monaco assets are picked up at next dynamic import (Next static path serves /vs).

- [ ] **EXT-07**: Conditional tab rendering in task detail page.
  - File: `src/app/workspaces/[workspaceId]/tasks/[taskId]/task-page-client.tsx`
  - Without rg installed: hide "搜索" tab entirely (not display install prompt inline)
  - Without Monaco installed: hide "文件" tab (file tree + editor) entirely
  - "Diff" / "终端" / "预览" tabs unaffected (those don't depend on rg/Monaco)

- [ ] **EXT-08**: Migrate `code-search.tsx` to consume `useExtension('rg')` instead of importing `checkRgAvailable`/`installRg` directly. Inline install button moves to Settings (Phase 72); when rg is missing the search tab itself is hidden, so the inline `<RgNotInstalled>` panel is removed.

- [ ] **EXT-09**: Decouple Monaco copy from npm `postinstall`. Remove `node scripts/copy-monaco.js` from `package.json`'s `postinstall` chain. Script remains; only `installExtension('monaco')` triggers it.

## Extensions Settings UI — Phase 72

Surface extension management as a dedicated tab in Settings so users can install / uninstall
at any time, see installation status, and reach official docs.

- [ ] **SETTING-EXT-01**: Settings page gains a new "Extensions" tab in the sidebar.
  - File: `src/components/settings/settings-page.tsx`
  - Position: between "搜索参数" and "Agent 配置" (or wherever feels natural; pick during planning)

- [ ] **SETTING-EXT-02**: One status card per extension (rg, Monaco). Card layout:
  - Icon, name, ~size, description
  - Status row: ✓ installed (with version + path) OR ○ not installed
  - Action buttons: Install / Reinstall / Uninstall (disabled when busy), 访问官网 (opens `homepageUrl` in new tab), 重新检测

- [ ] **SETTING-EXT-03**: Install / uninstall buttons show inline progress state (spinner + "安装中… / 卸载中…"). On success: toast + auto-refresh the card. On failure: toast.error with truncated error message + retry hint.

- [ ] **SETTING-EXT-04**: Cards driven by the `Extension` registry — adding a new extension definition automatically gets a card without UI code changes.

## Onboarding Integration — Phase 73

First-launch wizard adds a step that lets users opt-in to extensions before reaching the empty
workspace. Default-on so new users get full experience; users who skip see a hint about Settings.

- [ ] **ONBD-EXT-01**: Onboarding wizard gains a new step "扩展启用" between existing steps.
  - File: `src/components/onboarding/onboarding-wizard.tsx` (Phase 67 creation)
  - Step renders one row per extension (name + description + size + checkbox + 访问官网 link)

- [ ] **ONBD-EXT-02**: Both extension checkboxes default to checked. User can uncheck either before pressing "下一步".

- [ ] **ONBD-EXT-03**: When user unchecks any extension, show inline hint: "未启用的扩展可在 设置 → Extensions 中随时启用". Hint visible right under the checkboxes.

- [ ] **ONBD-EXT-04**: On "下一步" click, install all checked extensions in parallel via `Promise.all([installExtension(id), …])`. Show step-level progress overlay (spinner + per-extension status). On any failure: continue to next wizard step but persist a SystemConfig flag `onboarding.extensions.failed = ['monaco']` so a deferred toast surfaces on first workspace load.

- [ ] **ONBD-EXT-05**: Persist user's selections to `SystemConfig`:
  - `onboarding.extensions.requested` = comma-separated list of extension ids the user opted in
  - `onboarding.extensions.completed` = comma-separated list of ids that successfully installed
  - Used by Settings tab to show "在引导页选择安装但失败" affordance

## Future Requirements (Deferred)

Not in v1.2 — explicitly held back:

- **Build & Distribution slimming** (改 `monaco-editor` 为 optionalDependencies；削减 npm pack tarball；更新 `release-smoke.js` 验证；体积报告) — owner: separate later milestone (provisional v1.3)
  - Reason: Phase 71-73 deliver the user-facing extension experience without touching publish flow. The dist改造 has its own risk profile (publish breakage) and deserves a focused milestone.

- **Other extensions** (Claude Code 二进制 / Codex / Gemini CLI multi-provider / Mermaid renderer / etc.) — once the model is in place, extensions can be added one definition at a time. Future milestones can pick up more.

- **Per-workspace 启用/禁用** — current scope is global (一台机器装一次)。如果未来需要 A workspace 用搜索、B workspace 不用，再单独立项。

## Out of Scope

| 项 | 理由 |
|----|------|
| Git 插件化 | git 是项目的强依赖，命令行 git 由用户机器自带，包体积上没占用，不需要可选 |
| 真插件系统（manifest / 第三方扩展） | 远超 v1.2 范围；v1.2 只统一现有 rg + Monaco，给底子，不开发布平台 |
| 自动更新已装扩展 | 装/卸够用；用户自己 reinstall 就是更新 |
| 扩展间依赖关系 | rg / Monaco 互相独立，不需要依赖图 |
| 网络代理 / 镜像源配置 | 用户能用 pnpm 装 Tower 本身就说明网络通；遇到墙再说 |
