## Local gate results

The following gates passed from the main project directory without using port
3000 or the user's production Tower data:

- frozen pnpm workspace resolution after all package names, dependency edges,
  imports, test mocks, aliases, CI filters, and the lockfile moved to
  `@tower-org`
- builds and typechecks for the SDK, Runtime, and all three built-in providers
- package tests: 200 passed across the five internal packages
- Qwen extension typecheck, build, and 4 tests
- root TypeScript check
- standard `pnpm lint` after generated build, Monaco, and worktree trees were
  added to the global ignore list
- full root test suite with Tower task-terminal variables removed: 213 files
  and 2,022 tests passed; 6 files skipped and 27 tests remain todo
- Next.js 16.2.1 production standalone build
- VitePress documentation build
- deterministic Catalog generation and Runtime validation for one extension
- fixed release-identity gate and release-entrypoint policy
- npm package canary: 2,040 files and 59,836,070 bytes unpacked
- public-registry `npm pack --dry-run`: `@tower-org/cli@0.3.0`, output filename
  `tower-org-cli-0.3.0.tgz`, approximately 14.3 MB packed
- isolated packaged install smoke: installed 140 packages into a temporary npm
  prefix, reported `tower v0.3.0`, completed 13 first-run migrations, and
  verified the fixture plugin, API, Summary, Assistant, and Terminal plans at
  `http://127.0.0.1:54985`

The packaged smoke selected a dynamic loopback port, stopped its process, and
deleted its temporary HOME, npm prefix/cache, registry, and `TOWER_DATA_DIR`.
The existing service on port 3000 was not inspected, stopped, or reused.

The first unisolated test run demonstrated the expected task-boundary effect:
10 harness tests failed while the parent Tower terminal's `TOWER_TASK_ID` was
present. The release-style rerun removed all task/harness variables and passed
the full suite. This is environment isolation evidence, not a product failure.

## Remaining signed operations

No external state has changed. The following operations remain blocked until
the parent task obtains explicit authorization:

1. Transfer `jp-liu/tower` to `tower-org/tower` and update the local remote.
2. Push the reviewed migration commit to the canonical repository.
3. Configure the `npm-production` GitHub environment,
   `NPM_RELEASE_ENABLED=true`, and the `NPM_TOKEN` Actions secret.
4. Publish `@tower-org/cli@0.3.0` with public access and provenance.
5. Run `pnpm release:smoke:published`, which installs the exact version from
   npmjs.org into a clean temporary prefix and repeats first-run loopback smoke.
6. Deprecate `tower-studio@<=0.2.60` only after the public smoke passes.
7. Create and push `v0.3.0`, then create the GitHub Release.

The release script deliberately does not perform pull, tag, push, or GitHub
Release operations. Its default mode performs verification and pack dry-run
only. Publication requires an exact `TOWER_RELEASE_APPROVED` value, a clean
worktree, the canonical remote, a missing registry version, public access, and
provenance.

  `.gitignore` fallback because the package uses an explicit `files` allowlist.

## Rollback state

There is no npm version, remote transfer, pushed tag, or GitHub Release to roll
back yet. Before external execution, retain the current personal-repository
remote URL and verify every irreversible step independently. Once npm publishes
a version, that version number is immutable; prefer deprecation or a corrective
patch release over unpublish except for a confirmed critical incident.
